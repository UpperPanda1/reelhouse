# RafTV

A fast, streaming-style website for browsing what is trending (TMDB) and playing or downloading titles from **BDIX sources**, hosted on **Cloudflare Pages**. Phone, tablet and desktop layouts; no framework; about 167 KB of app JavaScript on the home page (uncompressed); the video player loads only when you press Play.

| | |
|---|---|
| Discovery | Trending, popular, top-rated rows, search, "Because you watched", Continue watching and History (remove single titles, with Undo), named watch lists (TMDB, free key) |
| Accounts (optional) | Invite-only sign-up, sign-in, password change; history, lists, resume positions and settings sync across devices; admin page for invite codes and users |
| Details | Movie / series pages, seasons and episodes, cast, recommendations, trailer link |
| Streaming | BDIX servers (DhakaFlix, Circle FTP, FlixHub) and online sources (Fendrix, Hexion, Mavonyx) are queried **only when you press Play or Download**, never while browsing |
| Player | ArtPlayer: MP4, MOV, MKV, WebM, HLS; resume; next episode; source switching; keyboard shortcuts |
| Subtitles | OpenSubtitles search (official API or keyless fallback), upload your own; size, height, colour and background are adjustable |
| Download | Separate button on the movie page and on every episode; ranked list of sources with copy-link, VLC/MX/Infuse links and an `.m3u` playlist |
| Safety nets | Detects files a browser cannot decode (HEVC, AC-3/DD+) and falls back or warns instead of showing a black picture or silence |

Full design and implementation notes: **[docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md)**. Licensing: see **[NOTICE.md](NOTICE.md)** (parts of this project are GPL-3.0).

## Read this first: how a website reaches BDIX servers

The CloudStream plugin this is based on runs inside an Android app and can talk to any server. A website runs inside a browser sandbox, which changes what is possible:

* BDIX servers such as `172.16.50.12` are only reachable **from a BDIX-connected network**. Cloudflare's servers cannot reach them, so the lookup must run from **your browser** (or from a gateway you run on your network). That is why this project has no server-side BDIX code in the Cloudflare Function.
* From an **https** page, browsers block plain-**http** requests ("mixed content"), need the server to send **CORS** headers, and do not let scripts set `Referer` or `User-Agent`.

So there are three connection modes (Settings → Connection):

| Mode | When it works | Setup |
|---|---|---|
| **Direct** (default) | The BDIX server sends CORS headers and the browser allows the request. Chrome/Edge 142+ ask for "local network" permission for private IPs such as `172.16.x.x`; Firefox and Safari block http from https. Public-looking hosts (`new.circleftp.net:5000`, `15.1.1.50`) are blocked from an https page. | none |
| **Edge proxy** (automatic for Hexion) | Public https sites without CORS that accept requests from Cloudflare; the Pages Function fetches the pages for you. Only the exact hosts in `EDGE_PROXY_HOSTS` are allowed (default in `lib/api.js`: the Hexion/4kHdHub link chain). **As of Nov 19, 2026 Hexion's sites block Cloudflare** (the app shows "Hexion: needs gateway"): use the gateway for Hexion. | none; if Hexion shows "server error" (not "needs gateway"), its link domains moved: add the new ones to `EDGE_PROXY_HOSTS` |
| **Gateway** (needed for BDIX on `pages.dev`, and for Hexion) | Always, if the machine running it is on BDIX (for Hexion any internet connection will do). Sets `Referer`/`User-Agent`, adds CORS, streams video with Range support, forces real downloads. | run `node gateway/bdix-gateway.mjs` (below) |

**Online sources (no BDIX needed).** *Fendrix* (Cinejoy/Shegu) is called straight from your browser, never through the gateway; its videos are HLS from a server that refuses in-page players, so they play in browsers with built-in HLS (Chrome/Edge 142+, Safari, iPhone/iPad); in browsers without it (Firefox) they play **when a gateway is set** (the gateway fetches the video and rewrites its playlists), otherwise in an external player (VLC, MX Player via the source's *More* menu). *Hexion* (4kHdHub) is looked up through your gateway (the edge proxy is tried without one, but the sites currently refuse Cloudflare); its files are large releases, often with Dolby (DD+/DTS) audio that browsers play silently: the app warns and offers the external players. *Mavonyx* (the MovieBox apps' catalogue) is looked up straight from your browser; its real video files are only listed when the request names the movie's MovieBox page, which a browser cannot do and which MovieBox refuses to Cloudflare, so **on pages.dev Mavonyx needs the gateway** for that one request (it is used automatically when set). Its API answers only in some countries (it refused the US-based build machine with "Service not available in current region"; it worked for the owner in Bangladesh), so it depends on where *your* device is. Its plain video files (MP4, HLS) play in the built-in player; its DASH streams (`.mpd`) do not yet and are listed as "Unlikely to play here" with the external-player links. All three can be switched off in Settings → Sources.

The app tells you which situation you are in: **Settings → Test connection** reports each host as *reachable*, *reachable but blocked by CORS*, *unreachable*, *gateway token rejected* or *blocked by the gateway*.

> FlixHub is a BDIX server like DhakaFlix and Circle FTP (the original plugin lists it as "FlixHub FTP: BDIX").
>
> Not verified: the real BDIX/FlixHub/Circle servers were not reachable from the environment this was built in. Their response formats are taken from what the original scrapers parse (see the provider notes in the implementation doc). Run **Test connection** on your own network first.

## Quick start (local)

Requires Node 22+.

```bash
npm install
cp .dev.vars.example .dev.vars        # put your TMDB key in it
npm run dev                            # http://localhost:8788
```

`npm run dev` serves `public/` and routes `/api/*` through the same code the Cloudflare Function uses, and applies `public/_headers` (including the Content-Security-Policy).

### Get a TMDB API key (free)

1. Create an account at themoviedb.org.
2. Settings → **API** → request a key for personal use (the free tier is for non-commercial projects; the footer attribution this site already shows is a condition of use).
3. Use either the v3 **API Key** (32 hex characters) or the v4 **API Read Access Token**; the Function detects which one you pasted.

### Optional: OpenSubtitles

Without configuration, subtitles use the keyless Stremio "OpenSubtitles v3" addon. For the official API, create a consumer at opensubtitles.com and set `OPENSUBTITLES_API_KEY` (and optionally `OPENSUBTITLES_USERNAME` / `OPENSUBTITLES_PASSWORD`, which raises the download quota). Set `APP_NAME` to the name you registered there; it is sent as the API User-Agent (`APP_NAME v1.0`). Secrets stay in the Function; the browser never sees them.

## Deploy to Cloudflare Pages

**With Git (recommended):** push this folder to GitHub/GitLab, then in the Cloudflare dashboard: *Workers & Pages → Create → Pages → Connect to Git* and set

| Setting | Value |
|---|---|
| Framework preset | None |
| Build command | *(empty: the player and font are committed in `public/vendor/`)* |
| Build output directory | `public` |

Then *Settings → Variables and Secrets* and add `TMDB_API_KEY` (as a **secret**), plus the optional OpenSubtitles variables. Redeploy once after adding them.

**With the CLI:** `npx wrangler login`, then `npm run deploy`.

Notes

* `public/_routes.json` limits Functions to `/api/*`, so static files are served without counting against the Functions quota (free plan: 100,000 Function requests/day, 10 ms CPU each). Responses are edge-cached, so normal browsing uses very few.
* The site uses hash routes (`/#/movie/603`), so it needs no SPA fallback rules.
* **https vs http:** a `*.pages.dev` site is always https. If you want direct (non-gateway) access to plain-http BDIX servers, attach a custom domain and disable "Always Use HTTPS" for it, or use the gateway.

### Accounts (optional): sign-in, sync, invite codes

Without this the site works as before: history and lists live on each device. With it, people sign in (accounts need an **invite code** from you) and their history, lists, resume positions and playback settings follow them to every device.

1. Create the database (once): `npx wrangler d1 create raftv-accounts`. It prints a `database_id`.
2. In `wrangler.toml`, un-comment the `[[d1_databases]]` block and paste that `database_id`, then commit. (This project has a `wrangler.toml`, which Cloudflare treats as the source of truth for the Pages project's bindings, so bind the database there rather than only in the dashboard.) The tables are created automatically on first use.
3. Add two **secrets** (dashboard *Settings → Variables and Secrets*, or the terminal): **`ADMIN_USERNAME`** (e.g. `admin`) and **`ADMIN_PASSWORD`** (at least 10 characters; a long random one):
   `npx wrangler pages secret put ADMIN_USERNAME --project-name raftv`
   `npx wrangler pages secret put ADMIN_PASSWORD --project-name raftv`
4. Redeploy, open the site, *Settings → Account → Sign in* with those two values: that first sign-in creates the admin account. Then *Change password* there if you like; after the first sign-in the secret is no longer used to sign in (the database is).
5. *Settings → Account → Admin*: generate invite codes (one person or several, with an expiry), send them; see who joined; reset a forgotten password (gives you a temporary one to pass on); remove users; disable codes.

Security notes: passwords are hashed (PBKDF2-SHA256, 100 000 iterations by default, set `PBKDF2_ITERATIONS` to change), sessions are HttpOnly cookies, failed sign-ins are rate limited, invite codes are stored hashed and shown once. On the Workers **free plan** one hash at 100 000 iterations takes about 14 ms of CPU (measured on the build machine) against a 10 ms limit; if sign-in fails with a Cloudflare "exceeded CPU" error, set `PBKDF2_ITERATIONS=50000` (existing passwords keep working: each hash stores its own count).

Locally: `npm run dev` uses a SQLite file in `.wrangler/` as the database and reads `ADMIN_USERNAME` / `ADMIN_PASSWORD` from `.dev.vars`.

### Using the site on `pages.dev` (https)

A `*.pages.dev` address is always https. That is fine for TMDB, subtitles and the player, but it is the hardest case for **BDIX** (section "Read this first"). What to expect and what to do:

| Setup | What happens | Status |
|---|---|---|
| Gateway on the **same device** as the browser, address `http://127.0.0.1:8787` | Browsers generally treat loopback as a secure origin, so the https site may call it. Chrome/Edge may show a one-time "local network" permission. Safari may refuse. | Standard browser rules; **not verified here** (tests ran over http) |
| Gateway on **another device** on your network with TLS (`TLS_KEY`/`TLS_CERT`, e.g. a certificate from `mkcert` or a private-network tool) | https page → https gateway, no mixed content | Standard; not verified here |
| Gateway on another device over plain http | Blocked as mixed content | Will not work from https |
| No gateway ("Direct") | Only works if the BDIX server sends CORS headers **and** the browser allows the request (Chrome/Edge 142+ with permission, private IPs only). Circle FTP's public-range host and `15.1.1.50` are blocked from https pages. | Often fails: use Settings → Test connection |

Always set `ALLOWED_ORIGINS=https://<your-project>.pages.dev` on the gateway so only your site may use it, and use `GATEWAY_TOKEN` when it listens on a network address.

### Change the name or logo

The name and identity live in **one file**, and the logo is **one file**:

1. Edit `public/js/brand.js` (`name`, `tagline`, `themeColor`).
2. Replace `public/icon.svg` with your logo (square SVG works best). It is used for the header logo, the browser tab icon and the installed-app icon. To use a different file name, change `logo` in `brand.js`.
3. Run `npm run rebrand` (updates the page title/description/theme colour in `index.html` and the web manifest), then `npm test`. A test fails if those files drift from `brand.js` or if any module hardcodes the old name.
4. Redeploy.

Left unchanged on purpose: the `rh:` prefix of saved settings (changing it would erase every user's history and settings), `package.json`'s name and the gateway's internal name. If you use the official OpenSubtitles API, set `APP_NAME` to the name you registered there.

## The gateway

Run it on a machine that can reach your BDIX servers (your PC, a Raspberry Pi, a VPS in Bangladesh). Zero dependencies.

**Windows, no install (`raftv-gateway.exe`).** Download `raftv-gateway.exe` from the repository's *Releases* page (built by GitHub from this code: `.github/workflows/gateway-exe.yml`; push a tag such as `gateway-v1.0.0`, or run the workflow by hand and take the file from the run's *Artifacts*). Put it in its own folder and double-click it:

1. Windows may say "Windows protected your PC" (the program is not code-signed): *More info*, *Run anyway*. When the firewall asks, allow it on **Private networks**.
2. The window shows what to enter in RafTV, *Settings*, *Connection*: an **Address** (`http://192.168.x.x:8787`, for your phone) and a **Token**. On the same PC you can use `http://127.0.0.1:8787`.
3. Keep the window open while you watch; close it to stop.

The first start writes `raftv-gateway.json` next to the program: the token (kept, so your phone keeps working after a restart), `host` (`0.0.0.0` = reachable from your Wi-Fi), `port`, `allowedOrigins` (only `https://raftv.pages.dev`; add your own domain if you use one), optionally `allowPrivate`, `tlsKey`, `tlsCert`. Edit it and restart to change them; the environment variables below override it. Build it yourself with `npm run build:gateway` (Windows: run it on Windows; it makes a program for the system it runs on). Measured (Linux build of the same program): starts in about 0.04 s, about 60 MB of memory idle (mostly the Node runtime inside it), about 100 MB while streaming at full local speed, negligible CPU.

**What goes through the gateway** (nothing else does: the site itself, TMDB, subtitles and accounts never):

| Source | Through the gateway |
|---|---|
| DhakaFlix, Circle FTP, FlixHub | lookups and video (they are BDIX servers) |
| Hexion | lookups; video comes straight from the file host |
| Fendrix | nothing, except its video in browsers without built-in HLS (Firefox) |
| Mavonyx | only the request that lists the real files (it needs a Referer a browser cannot send, and MovieBox refuses Cloudflare); token, search and video go direct |

**From a phone (https site, gateway on your PC over plain http):** Chrome on Android 142+ asks once to allow access to devices on your local network for a private address like `192.168.x.x`; allow it. Other browsers may refuse an `http` gateway from an `https` page. Not verified end to end here (see `VERIFICATION.md`, section 14).

**With Node instead:**

```bash
node gateway/bdix-gateway.mjs                                   # listens on 127.0.0.1:8787, no token needed (loopback only)
HOST=0.0.0.0 GATEWAY_TOKEN=choose-a-secret node gateway/bdix-gateway.mjs   # reachable from other devices on your network
```

Then enter `http://127.0.0.1:8787` (and the token) in **Settings → Connection**.

| Variable | Meaning |
|---|---|
| `HOST`, `PORT` | Bind address (default `127.0.0.1:8787`). A non-loopback `HOST` **refuses to start without** `GATEWAY_TOKEN`. |
| `GATEWAY_TOKEN` | Required on every request except `/health` (`?k=` or `x-rh-token`). |
| `ALLOWED_ORIGINS` | Comma list of site origins allowed by CORS (default: any). Set it to your Pages URL. |
| `ALLOW_PRIVATE` | Private hosts the gateway may contact (default `172.16.50.12,172.16.50.14`). Loopback/private ranges are otherwise blocked; link-local and metadata addresses can never be allowed. |
| `TLS_KEY`, `TLS_CERT` | Serve over https. Needed if the site is https and the gateway is on a LAN address. Browsers generally treat `http://127.0.0.1` / `localhost` as a secure origin, so an https site can usually call a gateway on the same device without TLS (Chrome/Edge may ask a one-time "local network" permission; Safari may still refuse). **This was not verified in an https setup here**: the automated tests run the site and gateway over plain http on loopback. |

Traffic caveat: through the gateway, video flows *server → gateway → your device*. Keep the gateway on the same BDIX network as your device so the traffic stays local. Do not put it behind a public tunnel: that would send BDIX traffic over international links.

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Local server (static + API + `_headers`) |
| `npm test` | 166 unit and integration tests (server layer, gateway, providers vs. golden output, client logic, router, API client, branding) |
| `npm run e2e:media` | Generates the small test videos (needs `ffmpeg`) |
| `npm run e2e` | 38 browser end-to-end steps in headless Chromium (real gateway, mock BDIX server, real videos). Add a word to run matching steps only: `npm run e2e -- subtitles` |
| `npm run smoke:cf` | Runs the real Cloudflare runtime (`wrangler pages dev` / workerd) against a mock TMDB: 9 Cloudflare runtime checks of the Function, routing and headers |
| `npm run rebrand` | Syncs `index.html` and the web manifest with `public/js/brand.js` after you change the name or colour |
| `npm run check:docs` | Checks that the documentation still matches the code (paths, scripts, counts, versions, env vars) |
| `EXT_REPO=/path/to/cloudstream node scripts/make-golden.mjs` | Regenerates `test/fixtures/golden.json` by running the *original* CloudStream scrapers (only needed if you change a provider on purpose) |
| `npm run build:vendor` | Rebuilds `public/vendor/` from `node_modules` after changing player versions |
| `npm run gateway` | Starts the gateway |
| `npm run deploy` | `wrangler pages deploy public` |

The E2E run launches Chromium from the `@sparticuz/chromium` package with its security-relaxing flags removed (see docs), so CORS and mixed-content rules are enforced like in a user's browser.

## Layout

```
public/            deployed as-is: index.html, css/, js/ (ES modules), vendor/ (player, font)
  js/providers/    browser port of the eclipsia scrapers: DhakaFlix, Circle FTP, FlixHub, Fendrix, Hexion, Mavonyx (+ shared parsing)
  js/ui/           views: home, details, watch, sources sheet, settings, browse
functions/api/     the single Pages Function: all of /api/*
lib/               API router, TMDB client, subtitle service (shared by Function, dev server, tests)
gateway/           optional BDIX gateway (Node, zero dependencies)
dev/               local server and mock upstreams
test/  e2e/        automated tests
docs/              implementation notes and screenshots
```
